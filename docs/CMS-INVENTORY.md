# CMS inventory: what on the site is editable content

Phase 0 of "every editable thing is editable in the EmDash admin". Written 2026-10-03 from a read of the code on `main` (no code changed). Only the `case_studies` collection (plus its taxonomies `service`, `topic`, `stack`) is in EmDash today. Everything below is either in code, in the unused journal/photos Astro collections, or in an Astro build-time script.

Legend.

- **Kind**: **prose** (paragraphs, safe for a rich-text or text field), **repeated** (a list of like items, a natural EmDash collection or repeater), **designed** (tightly designed copy: length, line breaks or a word-level accent matter to the layout, so a free text field can break it).
- **Edit**: how often Nathan would realistically change it: **often**, **sometimes**, **rarely**.
- Sizes are approximate counts of strings or items.

Net: the only live CMS surface is case studies. Menus, Widgets, Sections, Redirects, Bylines, Comments, pages, posts, categories and tags are admin features with no site consumer.

## 7. Where the volume is, ranked

1. **Long prose pages.** About (~19 paragraphs), Services (~15 paragraphs + 6 FAQ), Privacy (13), Accessibility (10), Contact (6), Photography (6), Work index (6). Roughly 80 paragraphs and ~45 headings across 9 pages. Natural fit for EmDash `pages` (Portable Text), but About and Services interleave prose with designed layout, so they need sections or structured fields, not one rich-text blob.
2. **Repeated structured items.** Pricing (3 tiers + 3 add-ons), FAQ (6), services (3), why-it-costs (4), process steps (4), principles (3), now-sheet (2 + 2 + 3 + 3), contact select options (21), nav (about 5 in 3 places), HeroShowcase sites (5), photo captions (5), colophon rows (7), accessibility practices (5). About 90 small items. Natural fit for a handful of small collections or repeaters.
3. **Settings and meta.** `site.ts` (about 12 values), page titles and descriptions (about 25 strings), OG card titles (11), CTA banners (about 6 title and sub pairs). One settings record plus a per-page SEO record covers it.
4. **Designed copy (low value to move).** Hero headline with accent span, ProcessBand CTA, 404, ComingSoon, Terminal lines. Rarely edited, easy to break; keep in code or expose as constrained fields (lead and accent as two fields).
5. **Already in EmDash.** Case studies, clients (marquee), testimonials, results, designer note, Selected Work cards.
6. **Empty today.** Journal, photos, press, client logos, newsletter, booking URL.

## 8. Things that will bite a migration

- **Prerendered vs server-rendered.** `/colophon`, `/privacy`, `/accessibility`, `/contact`, `/photography`, `/journal/*`, `/404`, `/coming-soon` are still static. Reading EmDash needs `export const prerender = false`, a Cache-Control header (`CACHE_CONTROL` in `caseStudies.ts`), and Playwright, link check and Lighthouse already run against a URL, so tests do not change.
- **Hardcoded facts in prose that must stay in sync with code.** Services FAQ prices versus the CMS pricing tiers (the pricing field labels say so), contact budget brackets versus pricing floors, privacy and accessibility text versus the real analytics stack, colophon performance claim (rewritten in PR 2, since pages are no longer static HTML), LighthouseScore numbers.
- **JSON-LD derived from content.** FAQPage and Service schemas on /services are built from the `faq` and `services` arrays; a CMS move must keep emitting them from the same data.
