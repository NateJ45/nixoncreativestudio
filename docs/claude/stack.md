# Stack

What is installed and why. Read when choosing or wiring a library. The runtime dependencies are deliberately few: `astro`, `@astrojs/cloudflare`, `@astrojs/mdx`, `@astrojs/rss`, `@astrojs/sitemap` and `sharp`.

- Astro 7 with TypeScript in strict mode and `output: 'static'`. `trailingSlash: 'always'`, `compressHTML: false` (the headline's words are inline spans, and compression would join two that the formatter put on separate lines), `prefetch` on the viewport strategy so links preload as they enter the screen.
- MDX content collections for case studies and journal entries; a JSON-backed collection for the photography catalogue (empty today).
- Plain CSS. `src/styles/kit.css` is the shared stylesheet (tokens in `:root`); each page imports its own file from `src/styles/pages/`. There is no Tailwind, no utility classes and no `globals.css`.
- One typeface: Hanken Grotesk, one variable woff2 self-hosted at `public/assets/fonts/hanken.woff2` and preloaded in `BaseLayout.astro`. Two static `.woff` weights in `brand/fonts/` exist only so the OG generators can read the glyphs. No font package is installed.
- Plain processed Astro scripts, no framework: `src/scripts/kit.js` is shared (footage, the closing deck, quote bands, the dock highlight, the client sheet, the price hand, `[data-weigh]`) and each page has its own (`home`, `about`, `work`, `churches`, `prices`, `contact`, `study`, `not-found`). Motion is springs written in JavaScript (`ui.spring`). There is no animation library.
- No React, no shadcn, no Radix, no icon library. The /photography gallery has no implementation while that page is gated; a new non-React one is a pending item (`docs/PENDING.md`).
- No ClientRouter. Page changes are cross-document view transitions (`@view-transition` in `kit.css`), with scrolling native.
- Removed in the November 2026 redesign: Tailwind and `@tailwindcss/vite`, `prettier-plugin-tailwindcss`, shadcn/ui and its helpers, React, `@astrojs/react`, `react-photo-album` and `yet-another-react-lightbox` (the gallery packages), `astro-expressive-code`, plaiceholder (and the blur-placeholder step), the Bricolage Grotesque, Source Sans 3 and Bebas Neue font packages, the theme toggle and the dark theme, the Pause motion switch, the Lightbox and the old homepage sections. Earlier removals (EmDash, Starwind, PrimeReact, Lenis, `motion`, Partytown, the WebGL hero) are in git history.
- sharp for image processing at build time (the adapter's `imageService: 'compile'`) and for the OG card and icon generators.
- opentype.js (dev-only) for the OG image generators: `scripts/generate-og-default.mjs` (the fallback card) and `scripts/generate-og.mjs` (per-page cards into `public/og/`, run in the build chain). Both render Hanken glyphs to SVG paths, then rasterize with sharp, out of process (the CF prerender isolate has no node built-ins, so an `astro-og-canvas` route can't run here).
- `@astrojs/rss` for `/rss.xml` (case studies; `<link rel="alternate">` auto-discovery is in `BaseLayout`).
- `@astrojs/sitemap` for the sitemap, with a filter that leaves out `/coming-soon` and, while it is gated, `/photography` (`astro.config.mjs`).
- `Analytics.astro` loads the Cloudflare Web Analytics beacon as a plain `<script defer>` (Partytown was removed 2026-09-04: its sandbox cost more main-thread time than the 7KB beacon) and, when `PUBLIC_GA_ID` is set, the GA4 gtag after the `load` event. The two script tags live in `src/components/analytics/` (`CloudflareBeacon.astro`, `GoogleAnalytics.astro`); `Analytics.astro` reads the env and wraps each in its condition. Site events come from `src/lib/track.ts`.
- `@lhci/cli` (dev-only) for Lighthouse CI; see `.claude/rules/testing-ci.md`.
- `src/data/site.ts` as the single source of truth for contact info (name, email, phone, address, studio name, social URLs, tagline, domain), the closing's `firstConversation` and `replyPromise`, `bookingOpen`, and the optional `bookingUrl` and `newsletterUrl`.
- Web3Forms for the contact form. Spam protection is the form's hidden honeypot field (`botcheck`) alone; the hCaptcha widget was removed. To re-add it, restore the `.h-captcha` div, the `js.hcaptcha.com/1/api.js` script tag, and the captcha gate in the submit handler in `src/scripts/contact.js`, then turn hCaptcha back on in the Web3Forms dashboard (Web3Forms supports hCaptcha only, not Cloudflare Turnstile or Google reCAPTCHA).
- eslint (flat config) and prettier (`prettier-plugin-astro`) for linting and formatting, `node --test` unit suites in `src/lib/*.test.ts`, Playwright and axe-core suites in `tests/`, linkinator for the internal link check, and a GitHub Actions CI run on every push and PR. See `.claude/rules/testing-ci.md`.
- Cloudflare for hosting: a Worker serving the static build as assets (see `wrangler.jsonc`; build command `npm run build`, output `dist/`).
- GitHub for version control.
