# Components, code conventions, images

Moved out of CLAUDE.md. Loads when components or layouts are touched.

## Component organization

When building UI, reach for components in this order:

1. Existing components in `src/components/` that already match this site's design
2. A plain `.astro` component with native HTML (`<details>`, `<dialog>`, a real `<a>` or `<button>`) and a small `astro:page-load` script when it needs behaviour
3. The one remaining shadcn/ui primitive, `src/components/ui/button.tsx` (mostly used through `buttonVariants()` on an `<a>`)
4. Custom build otherwise. Ask Nathan before adding a dependency.

The 2026-10 overhaul (package 1.2) deleted Starwind, PrimeReact, the unused shadcn primitives and the Aceternity / Magic UI blocks (bento grid, spotlight, marquee, animated beam), along with SectionHeading, ClientLogos, PressMentions and the Embla testimonial carousel. They are in git history if one is ever needed; do not re-add them for decoration. `docs/agent/component-sources.md` is the old sourcing guide, kept for reference.

File naming:

- PascalCase for top-level components (`Hero.astro`, `SelectedWork.astro`, `ProcessBand.astro`)
- kebab-case for shadcn primitives in `src/components/ui/` (matches shadcn CLI convention)

### Custom Button variants

`src/components/ui/button.tsx` extends the shadcn defaults with two project-specific options for marketing CTAs:

- `variant="brand"` paints the button in `bg-accent` (NCS blue) with a subtle hover lift. Used on the Hero, footer closer, Header and MobileNav "Start a project" pills, and the contact form submit. The pill is `cn(buttonVariants({ variant: 'brand', size: 'cta' }), 'rounded-full')`, the hero's recipe; reuse it rather than inventing another CTA shape.
- `size="cta"` bumps padding and font weight to the marketing-button proportions. Pair it with `variant="brand"` for the standard recipe. The desktop header's "Start a project" CTA (which replaced the Contact nav link) uses this recipe but wraps it in `cn()` to dial the padding down so it fits the bar: note that `buttonVariants()` called directly does NOT run `twMerge`, so a padding override only takes effect through `cn()`.

All other shadcn variants and sizes are unmodified, so future `npx shadcn add` commands don't fight with these extensions.

### The site chrome ships no React (overhaul 1.4)

The theme toggle, mobile nav, back-to-top, copy email and /work filter are `.astro` markup plus small scripts that register on `astro:page-load` with a `data-bound` guard (CLAUDE.md never-break rule 7). Since overhaul 2.8 no page loads React (/photography is gated and renders no gallery), and `tests/no-react.spec.ts` fails if an `<astro-island>` or React chunk shows up on any route. Radix and `lucide-react` are gone: the chrome icons are inlined Lucide SVGs in `ChromeIcon.astro`, and `Button` has no `asChild` (style a link with `buttonVariants()` instead, through `cn()` when a class overrides a variant). Each control works or hides itself without JavaScript: the toggle and copy button are hidden under `html:not(.js)`, the /work sector tabs are plain `?sector=` links that leave every row showing, and the menu button is a plain link to the footer nav.

### Shared primitives (overhaul package 1.8)

Phase 2 pages are built from four parts. All of them are on `/colophon/parts/` (noindex, out of the sitemap, in `tests/routes.ts`), rendered with the real Stone Steps 50K captures; look at that page at 1440 and 320 in both themes after changing one.

- `Section.astro`: one band of a page. Props `rail` (the mono label), `railMeta` (ONE real fact, computed from data, never typed in), `tone` (`white` | `paper` | `ink`; ink is `.band-ink`), `prose` (body in columns 4 to 10 instead of 4 to 12), `hairline` (the top 1px `--line` rule, on by default), plus `labelledby` or `label` for the section's accessible name. Uses `.page-grid` inside `.ncs-container` and `py-section`. The rail sits in columns 1 to 3 and sticks under the header from lg; below lg it is one line above the body. Use it for every new page band instead of a hand-rolled `<section class="py-2xl">`.
- `BrowserFrame.astro`: the one frame for a client website. A 28px paper bar with the real host in mono and three neutral `--line-strong` dots (never red, amber or green), on the shared `.frame` (ring, shadow, `--radius-frame`). `variant="phone"` drops the dots and has no fake bezel. Prints the full URL on paper; keeps its edges in forced colours. Put a `Media` inside it. Only real, live client sites go in a frame.
- `FramePair.astro`: a desktop and a phone BrowserFrame overlapping, both showing the same site. Takes the full-page `shots/{slug}-home.png` and `{slug}-mobile.png` as they are; Media crops them from the top at build time. Sized in percentages, so it holds at 320. Optional `sizes` / `phoneSizes` for a narrower column, and `peek` (package 2.2): the desktop screen holds a taller crop (at most 2.5 widths deep) and pans down it while an ancestor with `data-peek-trigger` is hovered or holds focus. CSS only, eased back on leave, still under reduced motion and Pause motion.
- `Media.astro`: the one way to put a raster image on a page. A fixed aspect-ratio box (`ratio`, or the image's own shape) that is lazy by default; `lcp` makes it `loading="eager"` with `fetchpriority="high"` (one per page, the LCP image only). It never starts hidden: no opacity 0, no clip-path, no fade script; the optional blur `placeholder` is painted behind the image. With a `ratio` that differs from the source, the served file is cropped to it (`position`: `center` or `top`).

`.surface-card` is retired for new work: only real artifacts (client sites, photos, the form) get a frame, and everything else sits on a Section's surface. Existing `.surface-card` uses go as Phase 2 rebuilds each page.

- `HeroReel.astro`: the tilted wall of real client sites behind the homepage hero (five columns, desktop and phone captures, each column drifting at its own speed via a two-copy CSS loop that moves by exactly -50%). Data in `src/data/reel.ts`, captures in `src/assets/reel/` (re-shoot with `node scripts/capture-reel.mjs`). Decorative and `aria-hidden`; cards are mouse-only links to `/work/{slug}/`, and a click morphs the clicked frame into the study's stage (`src/scripts/reel-morph.ts`, overhaul 3.1). Full behaviour in `.claude/rules/homepage-and-pages.md`.
- `Heft.astro` (package 1.7): the weight signature. Wrap the heavy phrase of a page's H1 in `<Heft text="..." />`; it renders the `<b>` and fills it from weight 200 to 800 once on load (`--dur-heft` on `--ease-glide`, 90ms per word capped at 5 steps, under 2.5s in total; the hero passes its own `delay`, `duration` and `ease`). Each word is a one-cell inline grid over an aria-hidden reserve copy at 800, so CLS is 0, and only `font-weight` animates, never opacity. `reverse` runs 800 to 200 (the 404; its reserve sits at 500 so the drained words do not leave gaps). Under reduced motion, without JS or under Pause motion it renders its end state (800, or 200 for `reverse`). One per page, on the H1 only (ruling 9): the home hero, /about, /contact, /photography, /work, /services, every case study (the whole client name, package 2.4a), /colophon, /privacy and /accessibility (through `DocumentLayout`, package 2.9) and the 404 today. H1s with no heavy phrase yet stay static: /journal and the journal-entry titles.
- `src/scripts/motion.ts` (package 1.7, imported once by BaseLayout): the motion controller. Watches every `data-motion="loop"` element with an IntersectionObserver (`data-motion-offscreen`), mirrors the hidden tab onto `html[data-motion-hidden]`, wires every `[data-motion-toggle]` button (click flips the Pause motion state, `aria-pressed` mirrors it), saves the choice to `localStorage["ncs-motion"]`, and runs the IntersectionObserver reveal fallback where scroll-driven CSS is unsupported. Exports `isMotionPaused()`, `setMotionPaused()`, `prefersReducedMotion()` and `loopMayRun(el)` for script-driven loops, and fires `ncs:motion` on `document` when the state changes. The pre-paint half lives in the BaseLayout bootstrap. Rules in `styling.md` ("Motion").
- The Pause motion switch (package 1.7) is `MotionToggle.astro` since 2.1, in the footer's utility row and the mobile menu (see above).
- `CaseStudyCover.astro`: a case-study cover drawn through `Media.astro`, with its plaiceholder blur painted behind the image (no fade; until 1.8 it faded in from opacity 0, which hid the LCP image). Used by the homepage Selected Work fallbacks and the /work/[slug] stage only when a study lacks `shots/{slug}-home.png` or `mobileShot` (normally the stage is a `FramePair`).
- `SiteShowcase.astro` ("Walk the homepage", package 2.4b): the client's real homepage capture (`shots/{slug}-home.png`, found by `slug`) in a `BrowserFrame`, walked top to bottom by page scroll. Where `animation-timeline: view()` is supported, motion is allowed and Pause motion is off (`html:not([data-motion-paused])`), the frame sticks under the header inside a 220vh track and the capture slides up on a named view timeline over the track's `contain` range (the screen is a size container, so the last frame ends at `100cqh`); no script, no timer. Otherwise (reduced motion, Pause motion, no support, no JS needed either way) the frame's screen is a native scroll box: a focusable `role="region"` named "Scroll the {client} homepage" (the client from the collection), reachable with Tab and scrolled with the arrow keys (`tests/walk.spec.ts`). Stone Steps went from 875 KB to 403 KB of images with it. Props as before (`slug`, `alt`, `href`, `label`), plus optional `client`, `sizes` and `caption`; `variant` still parses but the zoom loop is retired. Re-shoot captures with `npm run capture:study <slug>`. Covers in `src/assets/case-studies/{slug}.png` are real hero screenshots of the same sites.
- `CourseLine.astro` (package 3.2, the Stone Steps study only, placed in its MDX under "The course, measured instead of described"): the real course as a route plan (from above) beside an elevation profile with a hairline at each loop, in the client's mark colour (`--cs-accent`, `--cs-mark-dark` in dark mode; no text in a client colour). A native range input (0.1 mi steps) moves a marker on both and reads out mile, loop, feet and grade, as the visible `<output>` and as `aria-valuetext`; dragging (or hovering with a mouse) across the profile scrubs too. The control is `hidden` until its script binds, so without JS only the drawings and caption show. Data: `src/data/stone-steps-course.ts`, generated LOCALLY by `node scripts/build-course-line.mjs` from the sibling `clients/stonesteps-50k/scripts/data/course-profile.json` (about 600 of its 1,128 real points, evenly spaced, nothing smoothed) and committed, because CI cannot read a sibling repo. Used on the Foundation for Reformed Theology, MAS Monograms and Stone Steps 50K case studies. Labels are paper chips with mono text on a `--line-strong` edge (no accent fill). Since 2.4b it is a wide row on a 12-column grid (screenshot 7 columns, words 5, stacked below md) on a panel that alternates paper and white: `tone` defaults to paper for `side="left"` and white for `side="right"`, so the usual left, right, left run alternates on its own. - GA4 events (package 4.1, `src/lib/track.ts`, wired once in BaseLayout): one delegated click listener sends `visit_client_site`, `book_call_click`, `contact_click` (any `mailto:` link, picked up without an attribute, or `data-cta-method="copy"` on the CopyEmail button) and `cta_click` (any other `data-cta` id, such as Size up's `size_up_send`), each with `cta_location` (`data-cta-location`, else the landmark); `[data-track-view="pricing_view"]` on the PricingTeaser H2 fires once per page; the contact form calls `track('generate_lead')` on a successful post. ## Code conventions

- TypeScript strict mode. No `any`.
- Comment generously, especially in components that future-Nathan might edit by hand.
- At the top of each component file, add a header comment marking it `// Safe to edit` or `// Foundation, edit with care`.
- Astro components for static content. Interactivity is a small `astro:page-load` script first; a React island only for something as heavy as the photo gallery.
- Prefer Astro's built-in `<Image />` and `<Picture />` components over plain `<img>` tags.
- Tailwind utility classes inline. Pull into `@apply` only when a pattern repeats four or more times.
- Use `clsx` or `class-variance-authority` for conditional classes once components get state-dependent styling.

## Image handling

- Source photos live in `src/assets/` so Astro can optimize at build time.
- Use the `<Picture />` component for art-directed images (different crops at different breakpoints).
- Always include `alt` text. `alt=""` is acceptable for purely decorative images.
- For any new image on an `.astro` page, use `Media.astro` (above). The `Photo` React island (`src/components/Photo.tsx`) is for the /photography gallery only. It expects a build-resolved src URL (typically from an Astro `import` of a JPG asset) plus width and height. The `placeholder` prop accepts a base64 data URL when blur generation gets wired later.
- For the photography gallery (package 4.6), use the `PhotoGallery` React island. It composes `react-photo-album` for the justified grid with `yet-another-react-lightbox` (Zoom + Thumbnails plugins) for the fullscreen viewer. Pass a `photos` array of `{ src, width, height, alt?, caption? }`.
- Tall full-page captures (`shots/*-home.png`, up to 10824px high) are never served whole into a card. `Media.astro` crops them to their box, and `FramePair`'s `peek` crop stops at 2.5 widths deep (the home's Selected work, package 2.2). State the real rendered box in `sizes` so a phone picks the 640w candidate, not 900w. Add a 640w step to `widths` whenever a new image fills a phone-width column. Home cards went from about 1000 KB to about 390 KB (2026-10-13).
- `plaiceholder` is wired for case study covers. The data lives in `src/lib/coverPlaceholders.json` (generated at build time from `src/assets/case-studies/{slug}.{ext}` by `scripts/generate-placeholders.mjs`), looked up by the `CaseStudyCover.astro` wrapper, which hands it to `Media.astro` to paint (blurred) behind the image. The image is never hidden while it loads. Naming convention: cover filename's basename must match the case study's .mdx slug, or the lookup misses and the wrapper falls back to its `bg-bg-soft` solid placeholder.
