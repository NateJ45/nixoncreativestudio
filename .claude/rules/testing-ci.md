# Testing, linting, and CI

Moved out of CLAUDE.md. Loads when tests, unit-tested libs, workflows or tool configs are touched.

The repo carries a light quality-gate layer, matched to the rest of Nathan's Astro + Cloudflare sites.

WCP is the reference for this standard; reid-design-site and mas-monograms carry the same shape. `docs/TESTING.md` is the map of what covers what.

- `npm test` runs the Playwright suites in `tests/` (`playwright.config.ts`) against the real build served from `dist/client`. Chromium runs everything; a WebKit iPhone 14 profile runs `smoke`, `a11y` and `reduced-motion` only. `PW_PORT` moves the port when another worktree holds 4321 (an existing server there is reused locally, so check which build it serves). The specs, by what they guard:
  - Every route (`tests/routes.ts`): `smoke` (200 and the studio name in the title), `a11y` (axe default rules, zero violations), `reduced-motion` (PORTABLE, card 61: nothing still running 2.5s after load), `reflow` (no horizontal overflow at 320px unscrolled, while scrolling and settled, and settled at 1440/1024/768), `cls` (largest layout-shift window under 0.05 at 1440 and 390), `page-weight` (PORTABLE, card 197; budgets in `tests/page-weight.config.json`), `first-viewport` (visible H1s, media and their ancestors start at opacity 1 and no clip-path; the `.me` portrait is exempt; each study's cover is its one eager, high-priority image; the home hand of clients is on screen at load), `no-react` (no `<astro-island>` or React chunk), `metadata` (title and description length and uniqueness, JSON-LD graphs, /services offers, `/llms.txt`, `/robots.txt`), `forced-colors` (a tier card, a price card and a window keep an edge), `csp` (every route served with the built policy as an enforced header, scrolled, with no violation; the sheet and the form post too).
  - The chrome and pages: `chrome` (with JavaScript off the top line, dock and closing are real markup; the dock marks the current page; a window opens the client sheet and Back returns focus; "Show me a random one"; the home ledger links all four sector pages; Home and "Dark mode" are words in the dock; the name is never clipped and "Call or email" fits at 320 and 390; cross-document view transitions and no client router; `_redirects` for the short names), `services` (tiers link the form, the three-question picker deals a card, the care table and FAQ, FAQPage JSON-LD equals the visible FAQ, no-JS view, the phone folds), `contact` (native post to Web3Forms with JavaScript off and the `#sent` panel; with it on, one question at a time, prefill, drafts, the brief, success focus, the error panel and the honeypot; every Web3Forms request is intercepted), `work-filter` (large desktop windows, the sheet, `?sector=`, `?view=list`, counts, no-JS rows), `sector-page` (/churches/ matches the church studies and is a CollectionPage, lines up with its hero, and Orangeburg's window keeps off the empty events band), `first-sunday` (the /churches/ "Try it" questions: the answer in words, the tap hint and chevrons, the phone above the questions on a phone, reduced motion, the tier list, no-JS), `lean-pages` (the three lean sector pages and the /work/ index by job), `one-page` (prints on one US Letter page), `testimonials` (each study with a quote shows it; home shows one band and About two; a band never touches the closing), `not-found` (a 404 that names the path, axe and 320px, no-JS), `colophon` (the named font and host are the real ones; the window is a link), `photography-gate` (noindex, sitemap and closing link follow the real photo count), `track` (GA4 events with `gtag` stubbed, no field values).
  - The case studies: `course-line` (the Stone Steps range input, 0.1 mi steps), `walk` (the capture scrolls inside the rail phone; a keyboard-scrollable box under reduced motion and without JavaScript), `media-weight` (every clip at most 1.5 MB with its three files; no video before a window plays; clips under reduced motion stay on the poster), `what-you-edit` (the editor chapter only where there is a `cmsShot`, with real size and alt).
  - Not in `npm test`: `visual.spec.ts` (below). `tests/unit/copy-rules.test.mjs` is the copy lint. `tests/routes.ts` is the route list: add a line when a prerendered page ships.
- `npm run test:unit` runs `node --test` over `src/lib/*.test.ts` (then `test:scripts` for `scripts/lib/*.test.mjs`): `kit-tokens` (every rendered token pair in `kit.css` at AA, plus the promises: one typeface, self-hosted, one light theme, motion standing down), `case-palettes` (each study's client pair, its accent as text on the page and on a card, and `order` running 1..n), `case-results` (every display-size figure names its source), `work-figures` (the /work What changed stack: figures read from the study bodies, the part-of-a-whole maths, each figure's capture, and `src/data/capture-sizes.json` matching the real stills and footage), `case-testimonials` (quote shape, and only the studies with a received quote carry one), `study`, `words`, `href`, `money`, `seo`, `schema`, `track`, `readingTime`, `sitemap-dates`, `live-scores` and `receipt` (the live receipt on /services gives the cost table's numbers for every row). `scripts/lib/client-weeks.test.mjs` checks the weeks script's Monday maths and that the committed JSON holds only week numbers and counts. They run under Node's native type stripping, so they import the `.ts` modules directly with no build step.
- `src/lib/kit-tokens.test.ts` (site-owned) is the contrast gate. New token pairs go there, and client pairs in `case-palettes.test.ts`. It exists because axe has no rule for focus-indicator or custom-border contrast, so a Lighthouse score can sit at 100 while a pair is unreadable. The math lives in `src/lib/contrast.ts` (PORTABLE).
- `npm run lint` runs eslint (flat config in `eslint.config.js`) over `src` and `scripts`. A hard gate in CI since 2026-09-06 (0 errors; a few unused-variable warnings remain and do not fail it). The old `eslint-plugin-astro` false positive (an HTML comment inside a `{ ... }` expression read as a JSX error) is gone because every such comment is a JSX comment now. Inside a template expression, comment with `{/* */}`, never `<!-- -->`.
- `npm run format` runs prettier across the repo (family config in `.prettierrc`: single quotes, semis, trailing commas, printWidth 100, `prettier-plugin-astro`; ignore list in `.prettierignore`). `npm run format:check` is the CI form. `prettier-plugin-astro` cannot parse a `<script>` nested inside a template expression, so a conditional script goes in its own component and the condition wraps the component (`ComingSoonGate.astro`, `src/components/analytics/`).
- `npm run check` is the quick gate: `astro check && npm run lint`. `npm run check:full` adds the unit tests and the build.
- `npm run test:copy` runs `tests/unit/copy-rules.test.mjs` over the built HTML (so after `npm run build`): no "we", "our" or "us" in rendered body text, because site copy is first person singular. It skips `<blockquote>`, `data-copy-ignore` elements and their children, scripts, styles and attributes. `playwright.config.ts` ignores `tests/unit/` so Playwright never picks it up.
- `npm run check:links` runs linkinator over `dist/client` after a build; every internal link must resolve (off-site URLs are skipped). The log must say "scanned N links" with N in the hundreds.
- `npm run check:slashes` fails on any slashless internal href in the built HTML. `trailingSlash: 'always'` is set, so write hrefs as `/about/` (and `/contact/?org_type=x`); pass render-time hrefs through `withTrailingSlash()` in `src/lib/href.ts`.
- `.github/workflows/ci.yml` runs on pushes to `main`, on pull requests, and by hand. Job `build`: `npm ci`, sync-check against the starter (on drift, `scripts/propose-drift.mjs` opens a PR in the starter, then the gate still fails), `astro check`, lint, format check, unit tests, build, copy lint, link check. `build` and `test` are required status checks in the `main` ruleset (PR plus green CI), so keep those job names and never add a path filter to `ci.yml`. Job `test` (parallel): Playwright browsers, `npm test`, and the `playwright-report/` artifact (14 days). Since overhaul 4.4 both jobs, and `lighthouse.yml`, restore `node_modules/.astro/assets` (Astro's optimized-image cache, keyed on `src/assets`, `src/content`, the Astro config and the lockfile) right after `npm ci`: encoding every image as AVIF plus WebP takes about two minutes on a cold runner against seconds when the cache is warm. The Playwright `webServer` timeout is 300s so a cold build still fits.
- `.github/workflows/lighthouse.yml` runs Lighthouse CI (`@lhci/cli`, config in `lighthouserc.json`) against the built static output on pushes to `main` and on PRs. **Accessibility is a hard gate at minScore 1** (the 100-a11y bar the studio sells), and so are LCP under 4.5s and CLS under 0.1; performance / best-practices / SEO scores and total byte weight are warnings so normal CI variance doesn't block a PR. It runs on `ubuntu-latest`; see Gotcha 9 in `docs/claude/gotchas.md` for why the local run is not trustworthy on Windows.
- `.github/workflows/visual.yml` (overhaul 4.3) is `workflow_dispatch` only and **not a required check**: it runs `tests/visual.spec.ts` through `playwright.visual.config.ts` on `ubuntu-24.04` (full-page screenshots: every route, 1440 and 390, light only, motion frozen). `playwright.config.ts` ignores the spec, so `npm test` and `ci.yml` never run it. They are Linux PNGs in `tests/visual.spec.ts-snapshots/`; regenerate only with `gh workflow run visual.yml --ref <branch> -f update=true`, which opens a PR, and push an empty commit to that PR's branch so CI runs (a bot push starts none). Detail: `docs/TESTING.md`.
- `.github/workflows/live-scores.yml` (overhaul 4.7) runs `scripts/measure-live.mjs` on `ubuntu-latest`, monthly (the 1st, 06:17 UTC) and by `workflow_dispatch`. The script runs the Lighthouse that ships inside `@lhci/cli` (mobile, default throttling) three times against the `liveUrl` home page of mas-monograms, presbyterian-academy, reid-design, stone-steps-50k and first-baptist-muncie (sites built end to end on Astro + Sanity + Cloudflare; WordPress and Wix studies are left out), takes the median of Performance, Accessibility, Best Practices, SEO, LCP and CLS, and writes `src/data/live-scores.json` with the ISO date measured. The workflow then branches, commits, opens a PR, and dispatches `ci.yml` and `lighthouse.yml` on that branch, because a PR opened with `GITHUB_TOKEN` (or an empty commit it pushes) starts no `pull_request` runs while `workflow_dispatch` is allowed; the dispatched `build`, `test` and `lighthouse` check runs report on the PR's head commit. It needs the repo setting that lets Actions create pull requests. It is not a required check and never touches `ci.yml`. `src/lib/live-scores.ts` (`liveScoreFact`, unit-tested) can turn an entry into a fact and hides any entry older than 120 days, but no page prints it since the redesign; the pure helpers in `scripts/lib/live-scores.mjs` are tested by `npm run test:scripts`.
- `.github/workflows/uptime.yml` curls the live site's key routes hourly and fails the run if any does not end at 200. Gated on the `SITE_URL` repo variable, which is not set yet (see `docs/PENDING.md`). Schedule is on because the repo is public and Actions minutes are free there.
- `.github/workflows/dependabot-auto-merge.yml` squash-merges a Dependabot PR (minor and patch only) once every check run on it is green. The `npm` ecosystem in `.github/dependabot.yml` also ignores every semver-major (starter PR #57): majors wait for one planned stack upgrade; the `github-actions` ecosystem is exempt. Formatter bumps (`prettier`, `prettier-plugin-*`) come in their own `formatters` group (starter card 92), so a release that reformats files reds only that PR and auto-merge skips it; run `npm run format` on its branch and push.
- `npm run parity capture` / `compare` is the **rendered-HTML parity harness** (`scripts/page-parity.mjs`, baselines committed in `scripts/.parity/`). It never builds; you build, it reads `dist/client`. Reach for it on any change that is supposed to be render-neutral. Deliberately not in CI, because its baselines are meant to be re-captured when markup legitimately changes and a gate that gets re-baselined is a gate that gets rubber-stamped.
- `npm run sync-check` diffs this repo's copies of the shared "library of record" files against `ncs-astro-sanity-starter` (point at it with `NCS_STARTER_DIR`). Four files are marked canonical here: `scripts/free-dist.mjs`, `scripts/with-workerd.mjs`, `scripts/sync-check.mjs`, and `src/lib/contrast.ts`. Read that repo's `PORTS.md` before editing any of them, and port a fix back rather than patching locally. **This is a CI gate since 2026-09-06** (PORTS.md card 36): the build job checks the starter out at `.ncs-starter` and runs the script against it on every push and PR, so drift fails the build instead of waiting for someone to run it by hand.
- `npm run free-dist` is the manual form of the `prebuild` hook (Gotcha 6 in `docs/claude/gotchas.md`).
- `docs/PENDING.md` is the authoritative open-patch and waiting-on-a-human queue; `docs/TESTING.md` maps which gate covers what. Both are registries: edit them in the same commit as the thing they track.
